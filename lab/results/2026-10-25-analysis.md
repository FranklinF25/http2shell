## Reading

1. Harness sanity holds: the benign control decodes byte-identically on both
   images (same output length and sha256), so the lab measures decoder
   behavior, not harness noise.
2. The 13-byte "hang" trigger does **not** distinguish the pair when fed whole
   and ended: both images reject it identically at `ERR__ERROR_FORMAT_CL_SPACE`
   (context-map space validation). This empirically confirms, for the Node
   pair, the #2427 note that small probes do not reach the vulnerable branch
   ("probe mode CANNOT distinguish patched … none reach the branch").
3. Interpretation (hypothesis, not yet proven): the recorded "hang" behavior of
   this byte sequence likely manifests only under a partial/interactive feed —
   a server that streams the request body and keeps the connection open, so
   the decoder parks in NEEDS_MORE_INPUT on a prefix instead of seeing the
   tail bytes that resolve to CL_SPACE. `probe.js` currently feeds the whole
   buffer and ends the stream in both modes.
4. Next experiment (candidate for the detector research line): a prefix-feed
   oracle — feed k bytes (k = 1..12), do NOT end the writable side, wait a
   bounded time. If the vulnerable build parks in NEEDS_MORE_INPUT while the
   fixed build errors cleanly at the same k (ideally
   `BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH`), that is exactly the
   bounded-cost safe differential oracle #2427 marks as open.

## Independent verification (2026-10-25 17:39 UTC)

A read-only independent verifier reran the matrix end to end
(`matrix-20261025T173959Z.log`): all observables identical across runs
(kind/code/errno/message/outBytes/sha256 per case), control sha256 equal, all
exits 0, no timeouts. The verifier also found a hygiene defect: the initial
`.gitignore` rule `*.log` silently excluded both evidence logs from version
control, so the T3/T4 commit originally referenced disk-only evidence. Fixed
by negating `!lab/results/*.log` and amending the commit — the original run
and the verification rerun are now tracked together as a determinism pair.
